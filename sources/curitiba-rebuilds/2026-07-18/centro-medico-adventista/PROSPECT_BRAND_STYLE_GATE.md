# Prospect Brand & Style Adversarial Gate

Use this gate for every speculative prospect website before publication. Technical correctness is necessary but cannot compensate for weak brand thinking or under-resolved styling.

## 1. Brand-source prerequisite

Do not begin visual design until the brief records:

- [ ] Official logo variants and their source URLs
- [ ] Colors sampled from verified brand assets, with hex values
- [ ] Existing typography or the closest justified system-safe substitutes
- [ ] Three words describing the prospect’s current visual personality
- [ ] Strongest existing headline/tagline language that the prospect already publishes
- [ ] Verified services, locations, and contact details
- [ ] Minimum visual asset set: one hero plus three usable project/detail images
- [ ] Public project names/captions and proof signals, when available
- [ ] Desktop and mobile screenshots of the original after loaders/animations settle
- [ ] Explicit list of brand equity to preserve and weaknesses not to copy

If the source lacks sufficient assets or facts, downgrade the deliverable to an early visual direction. Do not present it as production-complete.

## 2. Concept thesis

Before implementation, write one sentence completing:

> “This concept can only belong to **[prospect]** because…”

Reject the direction if the answer is only its industry, city, logo, or colors.

The concept must define:

- [ ] One recognizable compositional idea
- [ ] One typographic idea connected to the existing brand
- [ ] One image-treatment rule
- [ ] One deliberate color evolution
- [ ] One emotional promise drawn from verified public language
- [ ] One conversion path

## 3. Anti-template tests

Run all six:

1. **Logo-removal test:** Hide the logo. Can a reviewer still identify the brand personality?
2. **Competitor-swap test:** Could another local competitor replace the name without redesigning the page? If yes, fail.
3. **Squint test:** At thumbnail size, is the hierarchy intentional and distinctive?
4. **Five-second test:** Can a viewer state who the business is, what it offers, and what makes the page memorable?
5. **Below-fold test:** Does visual quality remain strong after the hero, or does it collapse into generic rows/cards?
6. **Mobile-native test:** Does mobile have its own rhythm and focal moments, or is it merely stacked desktop?

## 4. Visual release scorecard

Score each dimension from 1–5.

| Dimension | Required |
|---|---:|
| Brand fidelity | ≥ 4 |
| Distinctiveness | ≥ 4 |
| Hero impact | ≥ 4 |
| Below-fold art direction | ≥ 4 |
| Typography | ≥ 4 |
| Image quality/treatment | ≥ 4 |
| Mobile intentionality | ≥ 4 |
| Credibility/proof | ≥ 3 |
| Conversion clarity | ≥ 4 |
| Proposal persuasiveness | ≥ 4 |

**Pass conditions:** average ≥ 4.0; no dimension below 3; brand fidelity, distinctiveness, hero, below-fold, mobile, and proposal must each meet their threshold. A technical pass cannot override a visual fail.

## 5. Art-direction checklist

### Hero

- [ ] Strongest verified visual asset is not obscured by an excessive overlay
- [ ] Headline is emotionally persuasive and source-bounded
- [ ] Text placement respects the image focal point
- [ ] CTA is unmistakable without looking like generic SaaS UI
- [ ] Logo has sufficient presence and contrast

### Typography

- [ ] Type choice relates to logo/current brand rather than a category cliché
- [ ] Display and body voices are intentionally paired
- [ ] Line breaks are art-directed at desktop and mobile
- [ ] Small uppercase labels remain readable
- [ ] No “serif equals premium” default without rationale

### Color

- [ ] Exact retained colors are documented
- [ ] New colors have a stated purpose
- [ ] Accent color is used selectively, not decoratively everywhere
- [ ] Image colors remain alive; overlays do not flatten material detail
- [ ] Contrast is checked mechanically and visually

### Imagery

- [ ] No low-resolution image is enlarged into a major focal point
- [ ] No watermarked/social screenshot is treated as polished production imagery unless explicitly intentional
- [ ] Project imagery includes source/provenance in the evidence record
- [ ] Crops are separately approved at 1440×900 and 390×844
- [ ] Portfolio/proof is not simulated with unverified projects

### Page rhythm

- [ ] At least three distinct but related compositional moments
- [ ] No run of repetitive cards or ruled rows substitutes for art direction
- [ ] Each large section earns its height through brand, proof, or conversion value
- [ ] Section transitions vary density without feeling random
- [ ] The final contact area is as resolved as the hero

### Mobile

- [ ] Navigation communicates open/closed state and has visible focus states
- [ ] Tap targets are at least 44×44 CSS pixels
- [ ] Services and contact do not become excessively tall stacks
- [ ] Mobile includes at least one intentional edge-to-edge or cropped visual moment
- [ ] Headline, image focal point, and CTA remain above the first fold where appropriate

## 6. Proposal-page gate

The proposal must remain on a separate URL and must not leak into the production site.

- [ ] Proposal leads with opportunity/result, not legal defensiveness
- [ ] Prospect logo is not used in a way that implies official authorship
- [ ] Current-versus-proposed visual evidence appears near the top
- [ ] Three prioritized problems and three corresponding improvements
- [ ] Deliverables, dependencies, and explicit next step
- [ ] Technical audit details moved to an appendix
- [ ] Non-affiliation disclosure is clear but not repeated throughout
- [ ] No unsupported ROI, award, project, team, testimonial, or performance claim
- [ ] Proposal has its own sender identity or unmistakable “independent concept” framing
- [ ] Proposal is visually consistent with the concept but clearly a sales document

## 7. Mechanical checks

- [ ] 1440×900 and 390×844 viewport screenshots
- [ ] Full-page desktop and mobile screenshots
- [ ] Zero horizontal overflow
- [ ] Zero console/page errors and failed local requests
- [ ] Mobile menu opened and keyboard-tested
- [ ] Every local link and anchor resolves
- [ ] Production homepage contains no proposal/redesign/disclosure language
- [ ] Proposal page is included in build integrity and publication verification
- [ ] Published files match reviewed files by hash

## 8. Adversarial review roles

Before release, obtain three independent reads:

1. **Brand strategist:** “Why is this unmistakably this prospect?”
2. **Art director:** “Where does the visual system become generic or under-resolved?”
3. **Mobile/conversion reviewer:** “Where does persuasion or intentional design collapse on a phone?”

Any two reviewers identifying the same high-severity weakness blocks publication until fixed or explicitly waived.
